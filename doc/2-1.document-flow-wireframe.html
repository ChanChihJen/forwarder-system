Document Flow｜文件流程管理 Wireframe
以 Job 的 Execution 摘要與 Execution Center 完整節點為基礎，整理文件來源、產生、確認、上傳、同步與歸檔流程
定位建議：Document Flow 不取代 Execution Center，也不取代 HBL / MBL 操作頁。它是一個「文件流程總覽 + 文件狀態控管頁」，讓 OP / CS 快速知道每份文件目前卡在哪個節點、來源是內部產生或外部回傳、是否已同步到 Document Center。

歸檔原則
完成文件自動同步 Document Center；操作仍回到 Execution / HBL / MBL 節點。
文件來源與產生規則
文件來源類型主要資料來源誰負責是否由系統產生確認後行為
HBL Draft內部產生Job Party、Cargo、Routing、Container、Freight TermOP / 文件人員是，可套 HBL TemplateConfirmed 後鎖定主要欄位；修改需新版本
SI內部產生 / 匯出HBL + Shipment + Carrier BookingOP是，送 Carrier / Co-loaderSent 後等待 Draft MBL
Draft MBL外部回傳Carrier / Co-loader PDFOP 比對否，上傳與摘錄欄位確認後可等待 Final MBL
Final MBL外部回傳Carrier / Co-loader PDF / 紙本掃描OP否，上傳附件同步 Document Center，進入放單處理
報關文件混合來源客戶文件 + 報關行回傳OP / 報關行部分欄位由系統整理放行後回寫 Customs Execution 狀態
拖車 / 進倉文件外部回傳車行、倉庫、CFSOP / Vendor否，主要管理附件與時間完成後回寫 Trucking / Warehouse 節點
On Board / Release Evidence外部回傳Carrier / Co-loader / AgentOP否，記錄日期與附件回寫 On Board 與 Document Completed
關鍵設計：Document Flow 只做「跨文件狀態控管」。文件內容的正式編輯仍回到各節點，例如 HBL 在 HBL 管理、SI / MBL 在 Execution Center、報關在 Customs 節點。
